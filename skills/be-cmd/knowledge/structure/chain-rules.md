# 命令链规则（BlockFlow 规范）

这份规则是 `chains.js` / `layout.js` 的实现依据。改动布局或断链逻辑前先读它。

## 1. 链的模型

一条链 = 链头 + 若干**连锁命令方块**（`chain_command_block`）。相邻方块通过
`facing_direction` 指向下一格。链头只能是：

- `minecraft:command_block`（脉冲，红石触发一次）
- `minecraft:repeating_command_block`（循环，持续运行）
- 断链头（`testfor` / `execute`）——本质上是链首的特殊编码

**一条链最多一个循环命令方块。** 遇到第二个时，从它开始（含它）归入下一条链，
它成为新链头。

## 2. 断链头（broken head）

**断链是为了性能**：让链首的循环命令方块与后面的连锁命令方块**物理断开**，常态下只有
循环方块在跑，整条链身不参与每 tick 调度；需要时才用 `/setblock` 把它接上，跑完再接
回去。这样几十上百格的链在没人触发时几乎不耗性能。

断开的实现就是两个 `/setblock` 标记互相配合：

1. 链首（`testfor`/`execute` 循环方块）条件成立时，第一个标记执行
   `/setblock ~~~-1 chain_command_block ["facing_direction"=2]`，把下一格接成朝 `-Z`；
2. 第二个标记随后执行 `/setblock ~~~ chain_command_block ["facing_direction"=1]`，
   把**自己**改回朝上——于是链身跑完一轮又断开，回到“只有循环方块在跑”的状态。

所以第二个标记朝向 1（朝上）不是笔误，也不是要“修正”的错位，而是断链状态本身。


断链的意义在于让链首的循环命令方块和后续的连锁命令方块断开，导致常态下只存在循环命令方块被加载，用以减少卡顿优化运行速度

```
testfor 形式                              execute 形式
z=31  /testfor @a[...]                    z=31  /execute as @a run /setblock ~~~-1 chain_command_block [...]
z=30  /setblock ~~~-1 chain_command_block z=30  /setblock ~~~ chain_command_block [...]
z=29  /setblock ~~~  chain_command_block  z=29  /body...
z=28  /body...
```

- 识别时**不要求**命令以 `/` 开头，也不限制空格格式。
- 两个标记必须是 `/setblock`，且方块是 `chain_command_block`。`fill`、`clone`、
  `structure load` 即使带相对坐标也**不得**当作标记，否则长链会被误拆。
- 标记的相对坐标只认 `~~~-1`（第一个）与 `~~~`（第二个），比较时先去掉所有空白。
- 第一个标记的 `conditional_bit`：`testfor` 形式为 1，`execute` 形式为 0；
  第二个标记恒为 0。
- **第二个标记朝向是故意的**（通常 `facing_direction=1`，朝上）。不要修正它。
- gap 形式在标记之间多一个格子：
  - `testfor-gap` / `execute-gap`：两个标记之间隔一格；
  - `testfor-direct` / `execute-direct`：两个标记紧邻，**没有**占位方块。
- gap 里如果放的是命令方块，它是链的真实节点（`isAuxiliary`），导入导出都要
  保留它的类型、命令、条件与执行方式；普通方块或空气则作为虚拟空气占位，导出
  时变回空气，不参与计数。

### 四种形式对照

| 形式 | 标记间距 | 第一个标记 `conditional_bit` | 链身起点 |
|---|---|---|---|
| `testfor-direct` | 紧邻 | 1 | z=29 |
| `testfor-gap` | 隔一格 | 1 | z=28（gap 后） |
| `execute-direct` | 紧邻 | 0 | z=29 |
| `execute-gap` | 隔一格 | 0 | z=28 |

`testfor` 头的第一标记必须是条件方块（前一条 `testfor` 成功才接线），`execute` 头
不是（它自己就是接线动作）。第二标记恒为 `cond=0`，否则断链那一下会失败、链身
永远接不回去。

### 什么时候该加断链

- 链身长、但触发稀疏（菜单、签到、VIP、传送）——加，平时只剩循环方块。
- 链身每 tick 都要跑（时间推进、在线统计）——加也可以，但收益小；链身本来就在跑。
- 一条逻辑链超过 64 格 X 跨度——不能删命令，只能拆成两条逻辑链并用断链头衔接。

### 细分：合并还是拆分

结构侧只有两条结论：

- **合并** = 一个断链头带更长的链身，触发时同一 gt 跑完，常驻循环方块更少；
- **拆分** = 每段一个自己的断链头，段与段**不保证同一 gt**（同 tick 抢执行预算）。

代价怎么算、什么情况不能合/不能拆、要问作者哪六个问题，统一写在 `intake.md` §8；
`mcbe.js group FILE` 给出候选与两套代价，决策权在作者；`mcbe.js check --only chain` 复查断链标记。

### 加/拆断链的步骤

1. 先确定链的整体方向（`inspect FILE --chain N` 看链头 `facing`），整条链只有一个旋转角。
2. 链头改写成 `testfor <条件>` 或 `execute <定位> run /setblock …`，跟在它后面的
   两格写标记；链身从第三格开始。
3. 标记坐标只能是 `~~~-1` 与 `~~~`——它们的基准是方块自己（见下节），重排后也
   不随布局改写。
4. 跑 `check FILE --only chain`：标记数量、条件位、朝向、gap 归属都会报出来；再 `layout` +
   `verify` 确认命令文本没被二次旋转。

### 断链相关告警怎么读

- `broken-head-mismatch`：条件位或朝向和链头类型不符。
- `testfor-not-head`：`testfor` 出现在链中段（常见于把多条系统链误合并成一条链）——按文件分链部署即可，不是缺陷。
- `empty-command`：断链标记之间/链身里出现空命令方块。多半是命令被清空（本仓库
  的链 9 就踩过：空块正好在 `tp … rm=32` 那一格），当作断链缺陷处理，别当占位。

### `/execute … at @… run` 排除

`/execute as @a at @s run …` 里 `run` 之前出现独立的 `at @…`，说明它只是“以实体
位置执行”，**不是**断链头。`run` 之后的 `at @` 不影响识别。

## 3. 相对坐标识别

以下两种写法都要认：

```text
~ ~ ~-1       带空格
~~~-1         紧凑写法
~1.5 ~ ~-2    小数
```

只要命令里出现相对坐标三元组，就属于“相对坐标命令”。断链头只对
`setblock/fill/clone/structure` 这几类命令做判断，且只有 `/setblock` 能当标记。

### 基准点是命令方块自己，不是偏移量

`/setblock ~~~-1 …` 里的 `~~~` 是执行这条命令的命令方块本身，`-1` 是它沿 Z 的
偏移；不是“以 `~~~-1` 为原点再减 1”。同理 `tp @s ~~~` 的 `~~~` 落在方块所在格。
写相对坐标、改相对坐标、判断别人写的相对坐标，都先确认基准点。

BlockFlow 会把整条链摆到 -Z（`facing_direction=2`），因此命令里的 `~` 三元组要
按**整链方向**旋转一次（§6 的表），并且：

- 两个断链标记是例外：坐标永远写 `~~~-1` / `~~~`，布局靠这两个字面量识别，
  重排后也不改写；
- `^` 不是 `~`：它以执行者朝向为基准，命令方块执行时用方块自己的朝向，而布局
  会把朝向重算成 -Z。命令方块里的 `^x^y^z` 先换算成 `~` 再按方向旋转；只有
  `execute … rotated as …` / `facing …` 自带的 `^`（n-tree 的 `^^^d`）保持原样；
- 只旋转一次。导出→再导入不得再次旋转，`verify` 会对比每个命令文本。

## 4. 自闭环

- 2–4 个连锁命令方块首尾相接的回环是合法结构，必须原样保留。
- 检测闭环时要**排除**断链标记：向下断链时标记可能指回自己的 gap，形成几何上的
  2 格环，不能因此把整条链当成闭环。
- 超过 4 个方块的闭环不受支持，按普通链处理并给出警告。

## 5. 布局

```
链头 z=31，向 -Z 走到 z=0（第一行 32 格）
第二行从 z=0 向 +Z 走：
  普通链      31 格
  execute 蛇  30 格
  testfor 蛇  29 格
第三行反向，如此交替，y 逐层 +1
链 i 占 x = -2*i
```

- 最后一个方块的朝向按行奇偶取 3 或 2；行内方块朝向指向后一格。
- `testfor` / `execute` 蛇的第二行起容量分别是 29 / 30，用来容纳断链标记的
  错位；普通链是 31。
- 只有断链标记保留它“错误”的朝向（`facing_direction=1`），其余方块按布局重算。

## 6. 坐标归一化（只做一次）

导入时把整条链的相对坐标旋转到 **-Z 坐标系**：

```text
facing 2 (-Z)  → (x,  y,  z)      不变
facing 3 (+Z)  → (-x, y, -z)
facing 4 (-X)  → (-z, y,  x)
facing 5 (+X)  → (z,  y, -x)
facing 0 (下)  → (x, -z,  y)
facing 1 (上)  → (x,  z, -y)
```

- 旋转以**链的整体方向**为基准，一条链只旋转一个角度。按每格自身朝向旋转会把
  蛇形链的返回行转两次，命令就指向错误的位置。
- 归一化必须是幂等的：对已经排好版的 `-Z` 链再导入一次，结果不能变。
- 重排、编辑、反复导出都不得再次旋转；`mcbe.js` 通过“整体方向”保证幂等。

## 7. 导出分片

1. 先完成全部链的布局，再判断是否需要拆分。
2. 只有整体 X 跨度 > 64 时才拆分。
3. **只能在链与链之间拆**，不能截断单条链；单链自身 X > 64 直接报错。
4. 每个分片独立可用：命令方块、命令文本、结构化数据都要完整。
5. 分片后整体平移使 `min(x)=0`，`size_z` 不小于 32。
6. 空占位方块导出为空气，实体列表清空。

## 8. 不变量（可用来写断言）

```text
每个物理命令方块恰好属于一条链
每条 snake 链恰好包含 2 个 /setblock 标记
每条链最多 1 个 repeating
链内坐标唯一
导出后所有 x ∈ [0, spanX)，y ∈ [0, sizeY)，z ∈ [0, 32)
所有命令文本在 导出→读回 后保持不变
```

`mcbe.js verify` 与 `mcbe.js selftest` 检查的就是这些。
