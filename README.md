# BlockFlow

**BlockFlow 是一个面向 Minecraft 基岩版（Bedrock Edition）的 3D 命令方块链编辑器。**  
它可以读取并识别 `.mcstructure` 结构中的命令方块链，在 3D 场景中检查朝向、编辑命令与链属性，并将编辑结果导出为新的 `.mcstructure` 文件。

## 功能特点

- **3D 可视化：** 查看命令方块的位置、朝向和链条布局。
- **链管理：** 浏览、排序、复制、删除已有命令链，或创建新链。
- **多种编辑方式：** 在 3D 视图中编辑单个方块，也可以在文本模式中逐行修改整条链。
- **文件导入：** 支持 Minecraft 基岩版 `.mcstructure` 结构文件和每行一条命令的 `.txt` 文本。
- **属性编辑：** 修改方块类型、条件、执行方式、命令、注释和标记等信息。
- **辅助工具：** 搜索、批量替换、撤销/重做、自动保存、主题切换和运行日志。
- **在线与离线：** GitHub Pages 在线版本为主要使用方式；完整项目也包含本地 Three.js 和字体资源，可作为离线备用方案。

## 适用范围与使用限制

**BlockFlow 主要用于编辑已经成型、具有明确连接关系的命令链结构。** 如果一个结构中包含大量彼此独立、无法组成有效命令链的单个命令方块，编辑器在识别、格式化和重新排列这些方块时，可能使命令链布局过长，超过结构文件的尺寸上限。因此，这类以零散单个命令方块为主的结构不适合使用 BlockFlow 处理。

建议在导入前确认结构中的命令方块已经按预期组织成链。对于链数量特别多或包含大量独立节点的文件，请先拆分或整理结构，再导入编辑。

另外，当前导出功能只保存 BlockFlow 识别并编辑的命令链方块，不保留原结构中的普通方块、实体和其他非命令方块内容。请勿将导出文件当作原始完整建筑结构的无损副本。

## 导入文件

### 导入 `.mcstructure`

`.mcstructure` 是主要的导入格式，适用于 Minecraft **基岩版（Bedrock Edition）**。可从开始页面选择文件；如果已经进入编辑器，也可以从 **“管理链”** 面板再次导入结构。

导入后，BlockFlow 会尝试解析结构中的命令方块、方块朝向和命令链连接关系，并将识别到的链显示在 3D 场景和链管理面板中。

导入完成后建议检查：

1. 命令链数量是否符合预期。
2. 每条链的命令顺序是否正确。
3. 3D 场景中的方块朝向是否符合原结构。
4. 断链头是否被正确识别。
5. 是否存在空命令方块、孤立方块或无法明确归属的方块。

结构文件中可能包含编辑器不识别的内容。请留意页面提示和运行日志，并在导出前检查结果。

### 导入 `.txt` 命令文本

在 **“管理链” → “导入 TXT 指令”** 中选择文本文件。建议使用 UTF-8 编码，并保持**每行一条命令**。

TXT 适合快速导入命令列表，但纯文本本身不包含完整的方块位置、朝向、条件和红石设置。导入器会根据命令内容尝试判断链类型和特殊断链格式，因此导入后请检查命令顺序、链类型、朝向和循环关系。

**空行注意事项：** 文本行与物理命令方块并非严格的一一对应关系。3D 结构中可能保留空命令方块，但文本模式不会为这些空方块生成对应空命令行。请勿单纯根据文本行数推断 3D 场景中的物理方块总数。

## 断链头与命令链识别规则

本节说明 BlockFlow 如何识别特殊的**断链头**，以及导入后应该如何检查。这部分规则尤其重要：断链结构依赖命令内容和方块朝向共同表达，不能只看命令文本或只看方块排列。识别命令时，开头的 `/` 是可选的；例如 `setblock` 与 `/setblock`、`execute` 与 `/execute`、`testfor` 与 `/testfor` 均按同一命令类型处理。

### 1. 什么是断链头？

断链头是链条中用于表达特殊断链关系的命令方块。它通常具有以下特征：

- 它本身是一个命令方块；
- 它包含非空命令；
- 它的朝向与这条链中其余命令方块的常规朝向不同；
- 这个朝向异常是结构表达的一部分，而不一定代表用户摆错了方块。

**断链头不是普通的空方块，也不应该靠一个非命令方块来充当。** 当前约定的统一断链格式会使用命令方块表达断链头；导入器识别到特殊断链结构后，会尝试将命令整理为统一的断链头格式。

### 2. 为什么要检查朝向？

普通链条通常沿着约定的连接方向延伸，方块朝向可以帮助编辑器判断哪个方块属于哪条链，以及命令的先后关系。

断链结构会故意让一个命令方块的朝向与其余方块不同。BlockFlow 在识别时，会结合链条连接关系和朝向差异寻找这个特殊方块，而不是简单地把所有朝向不同的方块都删除或忽略。

尤其要注意以下例外：

- 如果朝向异常的命令方块指向的是**它前一个命令方块**，不能仅凭朝向差异就把它判为应忽略的错误分支。
- 如果某个方向异常的方块所指向的方块并非其前一个节点，导入器需要结合整条链的连接关系判断它是否为断链头，不能只依据单个方块做决定。
- 对于彼此独立的多条链，某一条链上的异常朝向记录不能影响另一条链的识别。

如果导入结果与原结构不符，请在 3D 视图中检查断链头及其指向，并查看运行日志。

### 3. 断链头的命令数量约定

在当前约定的断链格式中，第一条命令作为断链头，后续命令数量取决于断链头的命令类型：

| 断链头命令类型 | 断链头之后应有的命令数量 |
| --- | ---: |
| `execute` 或 `/execute` | 30 条 |
| `testfor` 或 `/testfor` | 29 条 |

这里的数量指**从第二条命令开始计算的后续命令数**，不包含第一条断链头命令本身。

因此，检查导入结果时：

- 如果第一条命令是 `execute` 或 `/execute`，请核对断链头之后是否有 30 条命令。
- 如果第一条命令是 `testfor` 或 `/testfor`，请核对断链头之后是否有 29 条命令。
- 不要把断链头本身重复计入上述数量。
- 编辑命令后，命令内容可能改变链条的识别方式；修改后请重新检查链类型、命令数量与 3D 朝向。

这些数量是 BlockFlow 当前断链约定的一部分，并不代表 Minecraft 游戏对所有命令链都存在这样的通用限制。

### 4. 导入时如何处理断链头？

建议按照以下流程操作：

1. **导入原始 `.mcstructure`。** 尽量使用从目标 Minecraft 基岩版环境直接导出的原始结构文件。
2. **确认链条识别结果。** 查看链管理面板中的链数量，并在 3D 视图中定位朝向不同的命令方块。
3. **核对断链头。** 确认它是非空命令方块，并检查它的朝向以及指向的方块。
4. **核对后续命令数量。** `execute`（可带或不带开头 `/`）断链头后应为 30 条；`testfor`（可带或不带开头 `/`）断链头后应为 29 条。
5. **检查统一格式。** 导入器识别特殊断链结构后，会尝试将命令格式化为统一断链头形式。导入后仍应检查命令文本和 3D 结构，不要只根据链名判断。
6. **导出到新文件。** 不要覆盖唯一的原始结构文件；先在目标游戏环境中验证导出结果。

### 5. 创建或修改断链

通过 **“管理链” → “断链”** 创建断链时，编辑器会生成一组命令方块，并自动写入用于转向的命令。

如果你通过文本模式或 3D 属性面板修改了命令，链条可能被重新识别为其他类型，也可能符合断链头的识别条件。修改后应检查：

- 第一条命令是否确实是预期的断链头；
- 后续命令数量是否符合对应约定；
- 断链头是否是非空命令方块；
- 朝向是否符合预期；
- 是否意外改变了其他链的连接关系。

如果需要稳定地导入特殊断链，优先使用 BlockFlow 生成的格式，或以已知正确的结构为模板；不要只手动改变一个方块的朝向就假设整条链一定会被识别为断链。

### 6. 空命令方块与断链头的区别

空命令方块与断链头是两种不同情况：

- **空命令方块：** 方块存在，但命令文本为空。除特殊断链识别规则外，空命令方块不应仅因为命令为空就从 3D 结构中消失。
- **断链头：** 命令方块存在，命令非空，并通过特殊朝向和链连接关系表达断链语义。

因此，3D 场景中显示的物理方块数量可能多于文本模式中的命令行数。文本模式不会为普通空命令方块单独创建空命令行；请同时使用 3D 视图与文本模式检查结构。

## 3D 场景操作

| 操作 | 用途 |
| --- | --- |
| 鼠标左键拖动 | 旋转 3D 视角 |
| 鼠标滚轮 | 缩放视角 |
| `W` / `A` / `S` / `D` | 在场景中移动视角 |
| `Space` | 向上移动视角 |
| `Shift` | 向下移动视角 |
| 移动端方向键 | 在当前屏幕平面内平移摄像机；按住可连续移动 |
| 点击命令方块 | 选中方块并查看属性 |
| 顶部“前 / 侧 / 顶” | 切换标准观察方向；移动端会按可用屏幕区域自动调整镜头距离，尽量完整显示当前范围内的命令方块 |

移动端底部控制台分为三个区域：左侧用于管理链（总览时显示“管理链”，进入单链后显示“文本模式”和“删除本链”），中央是摄像机平移方向键，右侧的“使用说明”按钮会打开完整 README 文档。方向键沿当前屏幕平面移动摄像机和观察目标，不会旋转视角或改变镜头距离；按住方向键可以连续平移。

链条较长或方块重叠时，可以切换“前 / 侧 / 顶”观察方向，再选择需要编辑的方块。遇到断链头或自闭环时，建议从多个角度检查朝向。

## 编辑单个命令方块

选中命令方块后，可以在属性面板中查看或修改：

- **方块类型：** 脉冲、链式或循环。
- **条件：** 无条件或有条件。
- **执行方式：** 根据界面选项设置为保持开启或红石触发。
- **命令：** 编辑命令文本。
- **注释：** 添加便于识别的说明。
- **标记：** 标记需要重点关注的方块。

属性修改后，请确认命令、类型、条件、执行方式和朝向符合预期。BlockFlow 用于编辑和导出结构，不会替你执行命令，也不会自动保证命令在目标游戏版本中有效。

### 插入与删除

在选中方块的属性面板中，可以使用 **“后插”** 在当前位置之后插入方块，或使用 **“删除”** 移除当前方块。操作后请检查整条链的命令顺序、朝向和连接关系，尤其注意断链头与自闭环。

## 管理命令链

点击顶部的 **“管理链”** 打开命令链管理面板。这里可以查看现有链、调整顺序、复制或删除链，也可以导入命令或创建新链。

### 调整顺序

按照面板提示拖动链条条目即可调整顺序。调整会影响导出结构中的排列位置；完成后建议重新检查链条位置与连接关系。

### 新增命令链

编辑器提供以下新增方式：

- **脉冲链：** 创建脉冲命令方块。
- **断链：** 创建一组命令方块，并自动写入用于转向的命令。
- **循环链：** 创建重复命令方块。

创建后可继续编辑命令和属性。若手动修改了命令或朝向，请再次确认链条是否仍符合预期类型。

## 文本模式

点击顶部 **“文本模式”**，可以按行查看和编辑当前命令链。此模式适合快速修改多条命令、粘贴命令列表或调整命令顺序。

- 每个非空命令行对应一条命令；3D 中的空命令方块不会因此自动生成空命令行。
- 编辑器支持自动换行和 Minecraft 命令语法高亮。
- 点击行号可以切换对应命令的条件状态。
- 点击 **“应用修改”** 才会将文本修改应用到命令链；点击“取消”会放弃本次文本编辑。
- 在文本编辑框中按 `Ctrl + Enter`（macOS 上为 `Command + Enter`）可以应用修改。

批量粘贴或重排文本后，请检查命令顺序、条件标记与断链头命令数量。不要把文本行数直接当作 3D 场景中的物理方块数量。

## 搜索与批量替换

### 搜索

使用顶部搜索框查找命令或相关内容。搜索结果可帮助你定位需要检查的命令方块；大型结构建议结合搜索与属性面板编辑。

### 批量替换

点击顶部 **“替换”** 打开批量替换面板：

1. 在“查找”中输入要匹配的文本。
2. 在“替换为”中输入替换后的文本。
3. 选择作用范围：**全部链** 或 **当前链**。
4. 查看匹配数量，确认无误后再点击 **“执行替换”**。

批量替换会影响所选范围内匹配的命令内容。执行前请确认查找文本足够具体；若结果不符合预期，可以使用撤销功能恢复。替换断链头命令后，还应重新核对断链头类型与后续命令数量。

## 撤销、重做与自动保存

- 顶部的撤销、重做按钮用于回退或恢复最近的编辑操作。
- 支持常用快捷键：`Ctrl + Z` 撤销，`Ctrl + Y` 或 `Ctrl + Shift + Z` 重做。
- 导入结构后，编辑器会在当前浏览器中建立可恢复的工作快照；后续每次有效编辑后，会自动更新保存内容（通常在操作完成后的短暂间隔内写入）。
- 自动保存内容保存在当前浏览器的本地存储中，不会上传到 GitHub Pages。下次使用同一浏览器、同一站点数据时，如果检测到上次未结束的编辑，页面会显示恢复提示。
- 自动保存不跨设备或浏览器配置文件同步。清理站点数据、使用隐私浏览模式，或浏览器限制本地存储，都可能导致恢复内容不可用。
- 页面切换到后台或即将关闭时，编辑器还会尝试立即写入尚未完成的自动保存任务。

**自动保存不能代替导出文件。** 重要修改完成后，请使用“导出命令链”保存独立的 `.mcstructure` 备份。自动保存用于恢复编辑会话，不是 Minecraft 结构文件备份。

## 导出结构文件

编辑完成后，点击顶部 **“导出命令链”**，在格式选择框中选择：

- **导出老版本格式：** 使用 `format_version=1`，`block_indices` 为两层 `List<Int>`，文件名追加 `-old`。
- **导出新版本格式：** 使用 `format_version=2`，`block_indices` 为两层 `IntArray`，内部结构使用 Zlib 压缩，文件名追加 `-new`。
- **两者都导出：** 分别生成 `-old` 与 `-new` 两个文件。

导出后建议：

1. 确认下载的 `.mcstructure` 文件已保存到正确位置。
2. 保留原始结构文件，避免覆盖唯一备份。
3. 检查命令顺序、方块类型、条件、朝向、断链头和循环关系。
4. 在目标 Minecraft 基岩版环境中，先使用备份副本验证导出结果。

> **重要限制：** 导出文件用于保存 BlockFlow 识别并编辑的命令链方块。原结构中的普通方块、实体及其他非命令方块内容不会保留在导出结果中。因此，导出文件不是原始完整建筑结构的无损副本。

对于自闭环等特殊结构，导出前请确认相关方块的位置和朝向仍然符合预期。BlockFlow 不会执行命令，也无法保证命令在特定 Minecraft 版本、世界设置或实验性功能环境中一定有效。最终效果需要在游戏内验证。

## 常见问题

### 打开在线页面后无法正常显示

请使用较新的 Microsoft Edge 或 Google Chrome，并确认浏览器支持 WebGL。可以尝试刷新页面、关闭后重新打开，或更新浏览器和显卡驱动。受管理或限制较多的浏览器环境可能限制部分功能。

### 离线打开 `index.html` 后页面无法正常显示

请确认使用的是完整项目目录，而不是单独复制的 HTML 文件。检查 `vendor/three-offline.js` 和 `textures/LXGWWenKai-Light.ttf` 是否仍在原位置。如果浏览器限制 `file://` 页面读取本地资源，请使用本地静态服务器或 GitHub Pages 在线版本。

### 3D 场景没有显示方块或贴图

请确认浏览器支持 WebGL，并检查浏览器控制台和运行日志。在线使用时请确认页面及同域资源加载完成；离线使用时请确认资源目录结构完整。

### 导入后没有识别出预期命令链

请确认输入的是 Minecraft 基岩版 `.mcstructure` 文件，而不是其他版本或其他格式。若使用 TXT 导入，请保证文本编码合理且每行一条命令。自动识别需要根据方块连接、朝向和命令内容推断链结构；请检查断链头和运行日志，并在必要时手动调整。

### 断链头后面的命令数量不正确

先确认第一条命令属于哪种断链头：`execute` 或 `/execute` 后应有 30 条命令，`testfor` 或 `/testfor` 后应有 29 条命令。这里不包括第一条断链头命令。再检查是否把空命令方块误当成文本行，以及朝向异常的方块是否确实属于断链头。

### 3D 方块数量比文本行数多

这是可能出现的情况。3D 场景保留物理空命令方块，而文本模式不为这些空方块生成对应空行。检查结构时请同时参考 3D 场景和文本模式。

### 重新打开后没有出现恢复提示

自动恢复依赖同一浏览器配置文件中的本地存储。请尝试使用同一浏览器、同一站点地址，并避免清理站点数据。隐私浏览模式或浏览器存储限制可能导致无法恢复。即使恢复提示正常出现，也建议定期导出 `.mcstructure` 作为独立备份。

### 导出的文件中缺少原建筑的普通方块或实体

这是当前导出功能的设计限制：导出结果用于保存编辑器识别并编辑的命令链方块，不保留原结构中的普通方块和实体。请保留原始结构文件；需要保留完整建筑时，不要仅用导出文件替换原件。

### 导出的结构在游戏中无法导入或行为不符合预期

请保留原始文件和导出文件，确认游戏版本与结构格式匹配，并尝试在目标基岩版环境中重新验证。若仍有问题，可通过 GitHub 提交反馈，并说明操作系统、浏览器、游戏版本、复现步骤和相关运行日志。分享前请检查日志或结构文件中是否包含不希望公开的内容。
