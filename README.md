# BlockFlow 

BlockFlow 是一款用于 Minecraft 基岩版的命令方块链编辑工具，支持导入 `.mcstructure` 结构文件并且3D可视化编辑。

支持多种格式导入导出，目前支持
1. 1.26.50版本以上的新语法
2. 1.26.50以下的老语法（网易版老/execute指令语法）
3. 网易V3版本通用格式


## 工作区 UX

编辑器现在使用三个独立框，桌面端统一占页面横向 2/3 并居中：

- 顶部 52px：退出当前文件、文件名、命令数/链数、夜间、日志、说明、导出。
- 页面上方 3D 框：只放 3D 视口、前/侧/顶视图切换，以及多链模式下的返回主视图箭头；高度固定为 60vh，页面滚动时大小不变。相机使用键盘/鼠标操作。
- 下方工具框：搜索（点击图标展开）、替换、管理链、AI 辅助。管理链是一个小图标按钮，打开卡片排序弹窗。
- 管理弹窗直接显示链卡片，不显示“结构 / 链”标题、数量或筛选；新增按钮在弹窗标题行。卡片支持拖动排序、重命名和逐条删除，当前链高亮。
- 当前链文本单独作为一张卡片，保留行号、语法高亮、点击行号切换条件和失焦同步；高度约 25 行命令。
- 选中命令方块时，编辑弹窗位于视图切换下方，横向布局，宽度为 3D 视图的 2/3，内部可滚动。注释在命令上方，标记/后插/删除固定在标题栏右侧，标题空间不足时省略而不是挤压。
- 导出按钮展开为右侧胶囊菜单；提示使用堆叠 toast。
- 上传页是居中的结构导入卡片：品牌、说明、注意事项、文件拖放区；右上角眼睛打开使用说明，不显示轮换语录。文件选择后仍在本机解析。
- 搜索按钮打开页面顶部独立搜索层，宽度为页面 1/2；搜索层只有搜索框本体，框内右侧有 `×`，不扩大下方工具框。
- 顶栏/视图/链操作/弹窗操作使用符号按钮；链文本卡片保留“确认修改”（对勾）按钮。
- 上传页文字与操作按钮使用轻量 Fade In Up；进入编辑器时 3D 视图使用 Blur In；主题切换使用颜色过渡与图标旋转。
- 上一步/下一步在顶栏；命令数/链数在文件名右侧。
- 退出当前结构编辑使用确认 Modal；导出使用右上角胶囊菜单，选择版本后打开导出说明 Modal，确认后导出。
- 链文本卡片行号与代码共用滚动，行号不能单独滚动；当前链约 25 行高，所有行均可编辑。
- 主视图与链视图切换使用 View Transition 过渡，并在切换时立即渲染文本卡，避免延迟加载造成卡顿。
- 提示分为三类：右下角 macOS 风格 Toast、居中 Modal、从触发按钮处弹出的 Popconfirm；主框和卡片已移除阴影。
- Toast 从右侧滑入，底部颜色条显示剩余时间，右侧 `×` 可关闭，多条依次向上堆叠；命令方块修改确认使用 Toast。
- Modal 用于退出编辑、替换、重命名；通用确认不再承载“说明 + 输入框”，重命名使用独立 Modal。
- Popconfirm 从点击按钮处弹出，用于删除、清除、替换确认。
- 总视图没有当前链文本卡片时，剩余内容垂直居中。
- 只有一条链时默认进入链视图，并隐藏返回主视图箭头；多条链时从链列表进入链视图。
- AI 入口统一为“AI 辅助”。第一次点击且未配置时直接打开 AI 设置，之后可在 AI 对话里的设置按钮修改。
- 页面不显示滚动条，仍可用滚轮/触控板滚动。
- `Ctrl/Cmd+K` 或 `/` 聚焦搜索。

## 工程结构

BlockFlow 使用原生 ES Modules，无构建步骤，GitHub Pages 直接部署。

```text
blockflow/
├── index.html             # 只保留 DOM 壳和挂载点
├── styles/
│   ├── tokens.css         # 设计令牌
│   ├── upload.css
│   ├── editor.css
│   ├── components.css
│   ├── ai.css
│   └── workspace.css      # 工作区外壳（覆盖旧编辑器外壳）
├── src/
│   ├── main.js            # 启动、事件装配、搜索/导入/导出 UI
│   ├── state.js           # 共享应用状态
│   ├── log.js             # 运行日志
│   ├── scene.js           # Three.js 视口、相机、拾取与渲染
│   ├── inspector.js       # 方块检查器
│   ├── editor.js          # 链编辑、历史、自动保存、导入导出
│   ├── ai.js              # AI 会话入口（ES Module）
│   ├── ai/                # prompts / api / skill / context / actions
│   ├── core/              # nbt / structure / trace / layout / model
│   │                      #   broken-chain.js 是编辑器侧实现；技能侧 chain.js 独立且已漂移
│   ├── ui/                # dom / feedback / markdown / text-editor / theme
│   ├── data/              # 预生成技能 ID / 技能数据
│   └── skill-runtime/     # 浏览器内技能运行时
├── skills/be-cmd/         # 内置 AI 技能（随项目部署）
├── textures/
└── vendor/
```

本项目没有根目录 `package.json`；本地用任意静态服务器打开即可，不需要 `npm install`。

修改断链逻辑后，可运行 `node tools/check-skill-chain.mjs` 验证技能侧坐标旋转、标记识别和分类没有被改坏；修改缓存版本后，运行 `node tools/check-release.mjs` 检查所有内部 import 与 meta 是否一致。


## 1. 断链头的详细规则

### 1.1 断链头类型

支持两种断链头，必须同时保留：

- `testfor` 类型
- `execute` 类型

识别时不要求命令必须以 `/` 开头。例如：

```
/testfor @a
testfor @a

/execute as @a run ...
execute as @a run ...
```

### 1.2 支持的命令

断链头中的命令识别需要兼容以下命令：

- `setblock`
- `fill`
- `clone`
- `structure`
- `execute` 及其 `run` 后接的上述命令

不应因为命令前面有没有 `/`、空格格式或命令方块类型不同而导致识别失败。

断链头的两个标记方块仍必须是 `/setblock` 命令。`fill`、`clone`、`structure load` 等普通命令即使带相对坐标，也不得当作断链标记，否则长链会被误拆成一堆链。

### 1.3 相对坐标识别

- 只要命令中使用了相对坐标，就应纳入识别。
- 不要将识别范围限制为 `~~~` 或 `~~~-1`。
- 应根据命令实际使用的相对坐标判断断链位置。
- 不能只依赖固定坐标模板判断是否为断链头。

### 1.4 间隔方块识别

断链头之间可能存在间隔方块，需要识别并正确处理：

- 连锁命令方块
- 脉冲命令方块，不限朝向
- 普通非命令方块
- 空气方块

普通非命令方块的识别不应误判为断链头。水、岩浆等流体方块不应直接按照普通间隔方块处理，需单独测试。

### 1.5 多组断链

- 同一条命令链中允许存在多组断链头。
- 不能只识别第一组断链。
- 每一组都需要独立识别、处理，不能因为前一组识别成功就忽略后续断链。

### 1.6 断链后的坐标转换

识别完成后，需要根据原结构中的命令链朝向和命令实际使用的相对坐标进行转换：

- 将需要转换的相对坐标统一调整为 Z 轴方向。
- 只转换相对坐标，不得擅自替换原命令。
- 不得将 `setblock`、`fill`、`clone`、`structure` 等命令改成其他命令。
- 转换后必须保证命令指向的位置与原结构中的实际位置一致。
- 重排和导出时，所有链最终沿 **-Z** 方向延伸，链头与普通链身朝向 `facing_direction=2`；断链标记保留其格式要求的特殊朝向，不视为方向错误。
- 向下（`d0`）断链的标记可能指回 gap，形成几何上的 2 格循环；自闭环检测必须排除断链标记，不能因此把整条链保留为竖直方向。

### 1.7 辅助方块

辅助方块只存在于带间隔的断链形式（`testfor-gap` / `execute-gap`）中，位于断链头或第一个 `/setblock` 标记与最后一个标记之间。两个标记紧邻的 `testfor-direct` / `execute-direct` 形式没有辅助方块，不应凭空生成空白占位。

辅助方块按实际方块类型处理：

- **辅助方块是命令方块：** 脉冲或连锁命令方块必须显示对应贴图、加入当前命令链，并允许在链文本卡片和属性面板中编辑其命令、条件与执行方式。导入/导出必须保留其原始 `blockType`、`cond`、`auto` 与命令内容，内部标记为 `isAuxiliary`。如果辅助方块是循环命令方块，则按 1.9 的规则从它开始拆分为下一条链，它成为新链的链头，不留在原链中。
- **辅助方块不是命令方块（空气、普通方块等）：** 作为虚拟空气占位处理，只用于 3D 视图辅助显示和布局占位；不进入文本编辑、不参与命令方块计数、不能被选中，导出时转换为空气。

命令相对坐标只在首次导入/创建时归一化一次；断链重排和反复编辑时，不得二次旋转辅助方块、断链头或两个 `/setblock` 标记的相对坐标。

### 1.8 `/execute ... at @` 排除

如果命令以 `/execute` 开头，并且在 `run` 之前出现独立的 `at @...` 子命令（例如 `/execute as @a at @s run ...`），该命令属于普通的“以实体位置执行”指令，不得识别为断链头。`run` 之后的参数中出现 `at @` 不影响断链头识别。

### 1.9 循环命令方块约束

- 一条命令链最多只能有一个循环命令方块。
- 识别或导入时，如果链中再次遇到循环命令方块（包括断链 gap 中的辅助块、多断链头中的后续链头），从该循环命令方块起，它和后续所有命令方块自动归入下一条链。
- 该循环命令方块成为下一条链的链头，不得降级为链式方块，也不得把后续方块留在原链。
- 拆链后原链可能只剩链头或断链标记等片段，这是预期结果；导出时按拆分后的链分别布局。
- 普通链身、断链 gap 辅助块和多断链头都遵循同一规则，不设例外。

## 2. 导出时提供多个结构

导出时提供以下选项：

1. 旧版格式：导出旧版结构，文件名添加 `-old` 后缀。
2. 新版格式：导出新版结构，文件名添加 `-new` 后缀。
3. 网易版格式：导出符合网易版结构格式的文件，尽可能匹配网易版原始结构格式。
4. 全部格式：一次性生成上述所有格式。

### 多结构导出规则

- 当结构过大时，允许一次导出多个 `.mcstructure` 文件。
- 必须先完成所有命令链的完整布局，再判断是否需要拆分。
- 只有整体 X 轴尺寸超过 64 时，才考虑拆分结构。
- 拆分必须发生在完整命令链之间，不能从一条命令链中间截断。
- 单条命令链即使超过 64 格，也必须保持完整。
- 每个导出文件都必须能够独立使用，不能丢失命令方块、命令内容或必要的结构数据。
- 空白辅助方块在 3D 视图中用于辅助显示，导出时必须转换为空气方块。

## 3. 平台支持

- BlockFlow 仅支持桌面端浏览器（Windows / macOS / Linux）。
- 移动设备访问时会显示“仅支持 PC 访问”的提示，上传、编辑和 3D 场景全部禁用。
- 不提供移动端布局、触屏专用控件或相机方向键。

## 4. AI 助手

- 首次点击“AI 辅助”会打开 AI 设置，填写 API Key、Base URL 和模型；模型使用下拉框选择，也支持“自定义模型”。
- API Key 只保存在当前浏览器，不会上传到 BlockFlow 站点。建议使用单独的低额度 Key。
- 配置 Key 后，点击下方工具框的“AI 辅助”或检查器标题栏的 AI 按钮，会按当前范围打开新对话。
- 点击阅读按钮不会自动发送请求：弹窗会打开一条新对话，并把分析问题预填到输入框，用户确认或修改后点击“发送”才开始调用 AI。
- AI 请求会加载本项目内的 `blockflow/skills/be-cmd/SKILL.md`；如果路径不可用，会使用随页面打包的技能副本，不再提示找不到文件。
- 对话支持历史记录和多个会话：左侧列表按“全文分析 / 分链分析 / 文本范围”分组，可以切换、删除会话，`＋ 新对话` 创建新会话，记录保存在当前浏览器。
- 模型下拉框支持服务商要求的 `deepseek-flash` 与 `deepseek-v4-pro`；选择 `deepseek-flash`（V4.1 Flash）时会自动开启推理并把等级设为 `High`，请求会携带 `reasoning_effort: high`。
- 设置面板提供「测试连接」：使用当前填写的 Key、Base URL 和模型发送一次最小真实请求，并显示成功回复或 API 错误；这次请求会消耗少量 Token。
- 对推理模型兼容 `reasoning_content`：思考过程以灰色、自动换行的可折叠块显示，最终回答使用正常正文颜色（浅色主题黑色，深色主题浅色）；如果服务商只返回推理内容而没有 `content`，页面会显示推理内容而不是报“空内容”。
- 高级设置中的「最大输出 Token」默认留空，不再由页面固定为 8192；留空时请求不发送 `max_tokens`，输出上限由服务商和模型决定。需要时可以手动填写正整数。
- AI 回复支持 Markdown 渲染，包含表格、代码块、列表、标题和链接；每条回复下方显示输入/输出/合计 Token 用量。
- AI 思考过程会等完整返回后与正文一起显示，默认折叠为「思考过程」；展开后为灰色、自动换行、可滚动，用户未主动上滚时自动跟随到底部。最终回复使用正常正文颜色。默认思考过程和回复都使用中文，除非用户明确指定其他语言。
- 生成过程中可以取消；输入框和发送按钮保持可用，发送会追加到当前回答之后自动执行，并显示待发送队列。
- 支持给 AI 提交多个文本文件；附件会显示为标签，发送时作为数据分析。
- AI 超时时间改为 20 分钟。
- 没有消息的空会话在切换或关闭聊天窗时自动删除。
- 分链/文本会话会绑定创建时的链 UID；链被删除后，下一次在这个会话发送或点击操作时，会在所有链末尾新建一条链并重新绑定，不会误改其他链。
- 会话名称只能从左侧历史列表重命名；聊天顶部不能改。顶部删除和设置按钮已移除。侧边栏新建会话旁提供导入/导出/隐藏侧边栏图标，左下角只保留设置齿轮；删除仍使用历史会话的 ×。历史会话只显示名称，不显示链号或方块数。
- 会话内容可导出为 Markdown（内含可重新导入的隐藏 JSON）；支持导入会话和按文件自动保存。切换文件时清空当前显示，恢复该文件时恢复对应 AI 会话。
- 所有浏览器原生 confirm/prompt 已替换为项目已有的弹窗格式。
- AI 回复可附带隐藏的 `blockflow-actions` 操作块。页面不会显示 JSON，而是把多条建议合并成一个总按钮，例如“修复全部 3 项问题”；展开后可查看每一条具体改动。点击总按钮一次应用全部修改，再次点击取消本次修改；修改和取消都写入撤销历史，不再二次调用 AI。
- 操作支持批量替换、更新/插入/删除方块、新建链、替换整链和移动链。复杂修改由 AI 在 `replace_chain` 中给出精确完整命令；新建链优先断链，未指定位置时单链视图插入当前链下一条，总视图追加最后。
- 只读搜索/检查由 AI 自动调用；修改只能通过操作按钮执行。工具协议文档位于 [skills/be-cmd/knowledge/blockflow-tools/README.md](skills/be-cmd/knowledge/blockflow-tools/README.md)。
- 聊天输入框不再常驻命令按钮；输入 `/` 后才出现 `/检查语法`、`/检查逻辑`、`/生成测试`、`/评价系统`、`/讲解命令`、`/拓展系统`、`/查询id` 菜单，可用 Tab/方向键选择。
- 页面会以浏览器兼容方式加载 skill 的 `scripts/lib/syntax.js` 与 `rules.js`；每次发送前实际执行 `check --only syntax`（syntax.js）、`check --only chain`、`inspect`、`verify`，把结果注入 AI 上下文，AI 不需要 shell，也不会再回答“未执行”。
- 输入 `/check --only syntax`、`/check --only chain`、`/inspect`、`/verify` 可以直接让 AI 基于这些浏览器内工具结果回答；`/查询id` 会直接使用 skill 的 ID 数据查询。
- 部署到 GitHub Pages 时，仓库必须包含 `src/skill-runtime/lib/`（7 个转发层）、`skills/be-cmd/scripts/lib/`（真实实现）、`skills/be-cmd/SKILL.md`、`src/data/skill-ids-data.js` 与 `src/data/ai-skill-data.js`；缺少任一文件时 AI 技能运行时会退化为基础检查，并在控制台记录警告。
- 不再截断结构上下文。超大结构会自动按段加载全部分析，再汇总为最终回答；不会静默丢弃命令。
- 如果 API 服务商不允许浏览器跨域（CORS），请求会失败并显示提示；此时需要改用支持浏览器直连的服务商或自建代理。
