# BlockFlow 

BlockFlow 是一款用于 Minecraft 基岩版的命令方块链编辑工具，支持导入 `.mcstructure` 结构文件并且3D可视化编辑。

支持多种格式导入导出，目前支持
1. 1.26.50版本以上的新语法
2. 1.26.50以下的老语法（网易版老/execute指令语法）
3. 网易V3版本通用格式


## 1. 断链头的详细规则

### 1.1 断链头类型

支持两种断链头，必须同时保留：

- `testfor` 类型
- `execute` 类型

识别时不要求命令必须以 `/` 开头。例如：

```
/testfor @a
testfor @a

/execute as @a run ...
execute as @a run ...
```

### 1.2 支持的命令

断链头中的命令识别需要兼容以下命令：

- `setblock`
- `fill`
- `clone`
- `structure`
- `execute` 及其 `run` 后接的上述命令

不应因为命令前面有没有 `/`、空格格式或命令方块类型不同而导致识别失败。

断链头的两个标记方块仍必须是 `/setblock` 命令。`fill`、`clone`、`structure load` 等普通命令即使带相对坐标，也不得当作断链标记，否则长链会被误拆成一堆链。

### 1.3 相对坐标识别

- 只要命令中使用了相对坐标，就应纳入识别。
- 不要将识别范围限制为 `~~~` 或 `~~~-1`。
- 应根据命令实际使用的相对坐标判断断链位置。
- 不能只依赖固定坐标模板判断是否为断链头。

### 1.4 间隔方块识别

断链头之间可能存在间隔方块，需要识别并正确处理：

- 连锁命令方块
- 脉冲命令方块，不限朝向
- 普通非命令方块
- 空气方块

普通非命令方块的识别不应误判为断链头。水、岩浆等流体方块不应直接按照普通间隔方块处理，需单独测试。

### 1.5 多组断链

- 同一条命令链中允许存在多组断链头。
- 不能只识别第一组断链。
- 每一组都需要独立识别、处理，不能因为前一组识别成功就忽略后续断链。

### 1.6 断链后的坐标转换

识别完成后，需要根据原结构中的命令链朝向和命令实际使用的相对坐标进行转换：

- 将需要转换的相对坐标统一调整为 Z 轴方向。
- 只转换相对坐标，不得擅自替换原命令。
- 不得将 `setblock`、`fill`、`clone`、`structure` 等命令改成其他命令。
- 转换后必须保证命令指向的位置与原结构中的实际位置一致。
- 重排和导出时，所有链最终沿 **-Z** 方向延伸，链头与普通链身朝向 `facing_direction=2`；断链标记保留其格式要求的特殊朝向，不视为方向错误。
- 向下（`d0`）断链的标记可能指回 gap，形成几何上的 2 格循环；自闭环检测必须排除断链标记，不能因此把整条链保留为竖直方向。

### 1.7 辅助方块

辅助方块只存在于带间隔的断链形式（`testfor-gap` / `execute-gap`）中，位于断链头或第一个 `/setblock` 标记与最后一个标记之间。两个标记紧邻的 `testfor-direct` / `execute-direct` 形式没有辅助方块，不应凭空生成空白占位。

辅助方块按实际方块类型处理：

- **辅助方块是命令方块：** 脉冲或连锁命令方块必须显示对应贴图、加入当前命令链，并允许在文本模式和属性面板中编辑其命令、条件与执行方式。导入/导出必须保留其原始 `blockType`、`cond`、`auto` 与命令内容，内部标记为 `isAuxiliary`。如果辅助方块是循环命令方块，则按 1.9 的规则从它开始拆分为下一条链，它成为新链的链头，不留在原链中。
- **辅助方块不是命令方块（空气、普通方块等）：** 作为虚拟空气占位处理，只用于 3D 视图辅助显示和布局占位；不进入文本编辑、不参与命令方块计数、不能被选中，导出时转换为空气。

命令相对坐标只在首次导入/创建时归一化一次；断链重排和反复编辑时，不得二次旋转辅助方块、断链头或两个 `/setblock` 标记的相对坐标。

### 1.8 `/execute ... at @` 排除

如果命令以 `/execute` 开头，并且在 `run` 之前出现独立的 `at @...` 子命令（例如 `/execute as @a at @s run ...`），该命令属于普通的“以实体位置执行”指令，不得识别为断链头。`run` 之后的参数中出现 `at @` 不影响断链头识别。

### 1.9 循环命令方块约束

- 一条命令链最多只能有一个循环命令方块。
- 识别或导入时，如果链中再次遇到循环命令方块（包括断链 gap 中的辅助块、多断链头中的后续链头），从该循环命令方块起，它和后续所有命令方块自动归入下一条链。
- 该循环命令方块成为下一条链的链头，不得降级为链式方块，也不得把后续方块留在原链。
- 拆链后原链可能只剩链头或断链标记等片段，这是预期结果；导出时按拆分后的链分别布局。
- 普通链身、断链 gap 辅助块和多断链头都遵循同一规则，不设例外。

## 2. 导出时提供多个结构

导出时提供以下选项：

1. 旧版格式：导出旧版结构，文件名添加 `-old` 后缀。
2. 新版格式：导出新版结构，文件名添加 `-new` 后缀。
3. 网易版格式：导出符合网易版结构格式的文件，尽可能匹配网易版原始结构格式。
4. 全部格式：一次性生成上述所有格式。

### 多结构导出规则

- 当结构过大时，允许一次导出多个 `.mcstructure` 文件。
- 必须先完成所有命令链的完整布局，再判断是否需要拆分。
- 只有整体 X 轴尺寸超过 64 时，才考虑拆分结构。
- 拆分必须发生在完整命令链之间，不能从一条命令链中间截断。
- 单条命令链即使超过 64 格，也必须保持完整。
- 每个导出文件都必须能够独立使用，不能丢失命令方块、命令内容或必要的结构数据。
- 空白辅助方块在 3D 视图中用于辅助显示，导出时必须转换为空气方块。

## 3. 移动端专属

### 3.1 移动端界面

- 针对手机和平板屏幕优化布局。
- 控制按钮应适合触屏操作，避免按钮过小或过于密集。
- 重要功能应有清晰的入口，避免桌面端复杂布局直接压缩到移动端。
- 编辑区域应尽可能利用屏幕空间。

### 3.2 3D 视图触屏操作

- 单指拖动：旋转 3D 视角。
- 双指操作：缩放或调整视角。
- 触摸方块：选择对应命令方块。
- 触屏操作不能与页面滚动产生明显冲突。
- 需要提供方便的视角复位和整体结构查看方式。

### 3.3 移动端编辑

- 命令编辑区域需要适配手机输入法。
- 输入框应支持长命令编辑，不应因为屏幕较窄而影响内容查看。
- 需要避免键盘弹出后遮挡当前正在编辑的内容。
- 插入、删除、切换命令方块等操作应适合触屏使用。

### 3.4 移动端专属交互

- 为触屏设备提供独立的操作方式，不依赖鼠标悬停。
- 滚轮切换命令方块的功能，在移动端应提供对应的触屏操作入口。
- 切换命令方块时必须跳过空白辅助方块。
- 空白辅助方块不能被触摸选中，也不能打开编辑界面。
- 所有移动端操作都必须保留桌面端原有功能，不应因适配移动端而影响桌面端。
